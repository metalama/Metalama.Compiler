# CLAUDE.md

Repo-specific notes for Metalama.Compiler (a Roslyn fork built with Arcade + PostSharp.Engineering).

## NuGet cache: Docker/CI builds MUST use a repo-local `.packages` (Arcade #15970)

Building via the Arcade **toolset** (`…/microsoft.dotnet.arcade.sdk/<ver>/tools/Build.proj`) against the
**global** NuGet cache fails with:

```
error NETSDK1064: Package Microsoft.CodeAnalysis.Analyzers, version 5.3.0-2.25625.1 was not found.
```

(also `Microsoft.CodeAnalysis.BannedApiAnalyzers`, `MessagePackAnalyzer`) **even though the package is
physically on disk**. This is [dotnet/arcade#15970](https://github.com/dotnet/arcade/issues/15970):
toolset restore/resolution against the global cache is broken for `-ci`/official builds.

How to recognize it (vs. a genuinely missing package):

- `dotnet build Metalama.Compiler.slnf` **succeeds**, but the same projects **fail** when built as children
  of `Build.proj` (the Arcade toolset).
- Reproducible on a fresh agent, first run; the package directory and its `.nupkg.sha512` exist, and
  `[System.IO.File]::Exists(...)` returns `true` (both `\` and `\\` forms). So it is **not** a
  cache/disk/permission/path problem — it's the toolset-vs-global-cache resolution bug.

**Workaround (already used by `azure-pipelines.yml` and `eng/make-bootstrap.ps1`):** set
`NUGET_PACKAGES = <repo>\.packages` and `RESTORENOCACHE = true` so the toolset restores into a repo-local
folder instead of the global cache.

**`eng-Metalama/CustomizeDockerEnvironment.ps1`** (DockerBuild.ps1's per-repo customization hook) overrides
`NUGET_PACKAGES` to `<repo>\.packages` and sets `RESTORENOCACHE=true` for this reason. Do **not** remove that
override: `DockerBuild.ps1` itself defaults `NUGET_PACKAGES` to `$USERPROFILE\.nuget\packages`, which on the
machine-account TeamCity agent is the global `C:\WINDOWS\system32\config\systemprofile` cache that re-triggers
#15970. (`DockerBuild.ps1` is generated by `Build.ps1 generate-scripts` — never edit it directly; use the hook.)
Trade-off: `.packages` is repo-local and Swabra-wiped, so restores run cold; the `…systemprofile…` `-v` mount
DockerBuild still adds is now unused.

## Diagnosing Docker/CI build failures

MSBuild binlogs replay to text with no extra tooling:

```powershell
dotnet msbuild <Build.binlog> -flp:logfile=out.txt;verbosity=diagnostic   # full replay
dotnet msbuild <Build.binlog> -flp:warningsonly -nologo                    # warnings only
```

See the `/eng:fix-binlog-warnings` command. After `Build.ps1 build`, binlogs are under `artifacts/log`.
